Phases

Each phase starts only when the previous one's evidence is committed, so later work never rests on unverified numbers.

Phase 1 · Re-verify

G1 and G2. Refresh every live claim from an environment that reaches both hosts.

Phase 2 · Close coverage

G3, then the G4 scope decision. New checks enter at low or medium until the survey says otherwise.

Phase 3 · Integrate

G6, then G5. Release first, so ScrolIQ pins a tag rather than a commit.

Phase 4 · Package

G7, then refresh SUBMISSION.md, the dashboard and an October writeup from the committed artifacts.

Non-goals for October

  • No quality scoring here. Scan health, readability and ink scores stay in ScrolIQ; this repo measures integrity.
  • No new high codes without corpus-wide evidence. high means do not train, and it changes ScrolIQ's verdicts.
  • No full NGFF validation. The OME-NGFF validator already does that; we run alongside it, not instead of it.
  • No writes to public data. All tools stay read-only and anonymous.

How claims get made this month

  • Every number traces to a command and a committed artifacts/<date>-<name>/ with a README stating the command.
  • Live-state claims carry a date and are re-verified before they are restated.
  • Unreadable evidence stays UNKNOWN. It never counts as clean or as absent.
  • Check-code and severity changes are contract changes: fixture, golden output, CHANGELOG note with the new fingerprint.
  • A goal that slips is marked as slipped here, with the reason, rather than dropped.
